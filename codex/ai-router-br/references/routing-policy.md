# Política de roteamento

1. O agente principal é o modelo mais caro da sessão: decide, revisa, integra e fica com TIER 0. Execução vai para o degrau mais barato que dá conta, pela escada de `routing.*` (ver `models.md`).
2. A complexidade (`mechanical`, `simple`, `standard`, `complex`) escolhe o degrau. O TASK PACKAGE a declara; sem ela, o classificador infere pelo tier, pelo número de arquivos e por sinais de complexidade, e um plano mapeado em `steps` desce um degrau. Complexidade nunca altera o tier de risco.
3. DeepSeek é o primeiro degrau para trabalho mecânico e simples; Codex `gpt-6-luna` é o fallback barato. Coding padrão e complexo vai para Codex `gpt-6.1-sol` (low/high), com `gpt-6-sol` como fallback de modelo. `gpt-6-astra` nunca entra automaticamente.
4. Quando os workers externos estão indisponíveis ou bloqueados pelo ambiente (`dirty_worktree`, `tracked_secret`, `tracked_router_config`, `not_git_repo`), o último degrau é um subagente Claude (Haiku para mecânico/simples, Sonnet para padrão/complexo), nunca o principal. O principal só executa quando nem o subagente existe (host que não é o Claude Code).
5. Tarefa pequena pode ser feita diretamente pelo principal; não há delegação compulsiva. `router.auto_delegate: false` no config do projeto mantém tudo no principal (exceto executor forçado explicitamente).
6. Disponibilidade é checada antes do dispatch: binário e modelos do Codex (`~/.codex/models_cache.json`), formato da `DEEPSEEK_API_KEY`, se a tarefa cabe no DeepSeek (sem tools, só os arquivos enviados) e se o host tem subagentes. Degrau indisponível aparece em `skipped_candidates` e não é tentado.
7. DeepSeek tem no máximo 2 tentativas por padrão, e só repete em indisponibilidade transitória (rede, 429, 5xx) ou resposta vazia do modo JSON. Timeout, chave malformada e requisição recusada localmente não repetem. Sem loop barato infinito.
8. Fallback ocorre somente por indisponibilidade ou limite do degrau: spawn/CLI ausente, timeout, rate/usage limit, falha de autenticação (inclusive login não-ChatGPT no Codex e saldo insuficiente no DeepSeek), modelo recusado pela conta, erro de rede/API, `sandbox_unavailable`, ou resposta do DeepSeek truncada, vazia ou fora do formato e tarefa grande demais para ele. Nunca para mascarar teste quebrado, violação de escopo, commit do worker, repositório inseguro, comando de teste proibido ou budget. Nessas falhas o resultado traz `suggested_next` com o subagente Claude para a correção.
9. Todo resultado externo exige revisão do principal; `auto_integrate=false`. Trabalho de subagente Claude é revisado pelo `git diff` na árvore principal.
10. O processo Codex tem secrets removidos do ambiente e exige confirmação de login ChatGPT. O router não define `OPENAI_API_KEY` nem redireciona o Codex para DeepSeek.
11. `max_budget_usd` é um hard gate para DeepSeek porque é o worker pago por API. Para Codex por assinatura, os hard gates são timeout, escopo, max files, sandbox/worktree e revisão; o custo em créditos é controlado pelo modelo e esforço do degrau. `max_turns` é um limite de política/soft bound porque o CLI não expõe neste design um contador portátil de tool turns.
12. O config do projeto pode remover ou reordenar degraus da escada, nunca adicionar modelo ou complexidade.
13. O primeiro uso em qualquer projeto auto-inicializa `.ai-router/` e o bloco curto de regras; isso é infraestrutura local e reversível, não exige autorização. Um `config.yml` idêntico a um template anterior do plugin é atualizado sozinho; um editado à mão nunca é tocado.
