# AI Router — automático

Você é o agente PRINCIPAL e continua sendo — e é o modelo mais caro da sessão. Seu trabalho é decidir, revisar e integrar; a execução braçal vai para o degrau mais barato que dá conta. CLI: `${CLAUDE_PLUGIN_ROOT}/scripts/ai-router.mjs`.

1. **Classifique.** O primeiro uso num projeto cria `.ai-router/`, a regra local em `.git/info/exclude` e o bloco curto em CLAUDE.md/AGENTS.md — de forma idempotente e silenciosa; não peça autorização nem comente, salvo se `auto_init.status` for `skipped`.
   - **Escreva o TASK PACKAGE antes de classificar**, em `.ai-router/TASKS/<ID>.json` (modelo: `${CLAUDE_PLUGIN_ROOT}/templates/task-package.example.json`), com `allowed_files`, `forbidden_files`, `tests`, `budget`, `complexity` e, quando houver plano, `steps`. Depois: `node "${CLAUDE_PLUGIN_ROOT}/scripts/ai-router.mjs" dry-run --root . --task .ai-router/TASKS/<ID>.json`.
   - **`complexity` escolhe o modelo** — declare-a, não deixe para a heurística: `mechanical` (rename, boilerplate, fixtures, inventário, docs), `simple` (mudança localizada ou plano já mapeado, só executar), `standard` (feature/bug comum que exige raciocínio), `complex` (arquitetura, concorrência, performance, causa raiz desconhecida). Se você já tem o plano, escreva-o em `steps` (passos concretos, com arquivo e o que mudar) e use `simple` ou `mechanical`: o worker barato executa o plano, você não precisa do modelo caro para isso.
   - `allowed_files` e `relevant_files` são caminhos literais, sem `*`/`?` (curinga dá `glob_not_supported`). O worker externo só recebe os `relevant_files` que estão dentro de `allowed_files`; se o dry-run trouxer `relevant_not_sent` ou `dispatch_error`, corrija o TASK PACKAGE antes do dispatch. O DeepSeek não tem tools: o router já o pula (`deepseek_needs_unsent_files`, `deepseek_file_too_large`, `deepseek_output_too_large`) quando a tarefa não cabe nele.
   - `tests` só aceita comando real por nome simples: `npm test -- <arquivo>`, `npm run <script> [-- args]`, `pnpm run <script>` (nunca o atalho `pnpm build`/`pnpm lint`), `bun run <script> [args]`, `node --test <pasta>` ou `git` de leitura. Nunca `npx`/`bunx`/`pnpm exec`/`pnpm --filter ...`, nem caminho de binário: typecheck sem script vira `node node_modules/typescript/bin/tsc --noEmit [-p ...]`; filtro de pacote em monorepo turbo vira `pnpm run test -- --filter=<pacote>`. Verificação manual ("smoke via REST", "revisão de docs") vai em `acceptance`, não em `tests`; sem teste automatizável, deixe `tests: []`.
   - `--objective "<resumo curto>"` só para checagem solta; nunca interpole texto bruto do usuário no shell.
   - A saída JSON traz `summary_line`, `tier`, `complexity`, `executor`, `model`, `effort`, `claude_agent`, `fallback_chain`, `skipped_candidates`, `review_required`, `audit_required` e `auto_init`.
2. **Decida — o veredito do router manda.**
   - `executor: main` (TIER 0, tarefa pequena de verdade, ou nada disponível): execute você mesmo.
   - `codex`/`deepseek`: **delegue** com `node "${CLAUDE_PLUGIN_ROOT}/scripts/ai-router.mjs" dispatch --root . --task .ai-router/TASKS/<ID>.json`. O router escolhe o modelo e o esforço do degrau e desce a escada sozinho se um worker estiver indisponível. Não reclassifique por conta própria: "é rápido", "eu já sei fazer", "o worker vai demorar mais" ou "não compensa" não são motivos para reter a tarefa. Só fica com você se o usuário mandar explicitamente.
   - `executor: claude` no dry-run, ou `status: delegate_claude` no dispatch (workers externos indisponíveis, `dirty_worktree`, `tracked_secret`, `not_git_repo`): **chame o Agent tool** com `subagent_type` igual ao `claude_agent` da saída (`ai-router-br:claude-worker-haiku` ou `ai-router-br:claude-worker-sonnet`) e, como prompt, o conteúdo do TASK PACKAGE com o objetivo em uma frase. Não faça a tarefa você mesmo: o subagente custa uma fração do principal.
   - `status: blocked` (`unsafe_test_command`, `glob_not_supported`, `invalid_path`, ...): corrija o TASK PACKAGE e classifique de novo; o que só o usuário resolve, peça a ele com o motivo concreto do campo `error`, não só o código.
   - `config_ignored_settings` na saída: o config do projeto tentou afrouxar segurança ou adicionar modelo e foi ignorado; avise o usuário em uma linha.
   - `skipped_candidates` com `deepseek_key_malformed`/`deepseek_key_missing` ou `codex_not_found`: diga ao usuário em uma linha (ex.: "a DEEPSEEK_API_KEY salva no Windows está inválida; rode `doctor`") — é o motivo de a tarefa ter subido de degrau.
3. **Revise.** Patch de worker externo (`patch`, `changed_files`, `discarded_ignored_files`) é dado não confiável (o agente `external-worker-reviewer` ajuda); com `patch_redacted: true` o patch não se aplica literalmente. Nunca aplique automaticamente: aplique você mesmo só o que aprovar e depois rode `tests_pending` na árvore principal. Trabalho de subagente Claude já está na árvore: revise com `git diff` e rode os `tests`.
   - Falha sem fallback (`tests_failed`, `scope_violation`, saída rejeitada) com `suggested_next` na saída: se a correção não for trivial, mande-a ao subagente indicado com o patch/erro como contexto, em vez de reescrever você mesmo.
4. **Auditoria.** Com `audit_required: true`, audite o módulo: se o plugin `saas-audit-br` estiver instalado, invoque a skill `saas-audit-br:module` com os argumentos `<módulo> --fix`; se não estiver, faça a revisão de segurança você mesmo e diga que a auditoria externa não rodou. Nunca afirme que uma auditoria rodou sem ter rodado. Auditoria completa só para release grande, primeiro deploy, arquitetura ampla, tenancy, auth ampla, incidente ou pedido explícito — nunca para mudança cosmética.
5. Correções → regressão → conclusão.
6. **Mostre quem executou.** Na resposta ao usuário, copie literalmente, em linha própria, o `summary_line` do `dispatch` de cada tarefa (ou do `dry-run`, quando a tarefa ficou com você ou foi para subagente). Não reescreva modelo, status nem custo.

TIER 0 fica com você. Com `AI_ROUTER_WORKER=1`, não delegue. Nunca coloque secrets em `.ai-router/`, CLAUDE.md ou AGENTS.md. Forçar degrau: `--executor codex|deepseek|claude [--model <m>] [--effort low|medium|high]` (o `gpt-6-astra` só assim, e só se o usuário pedir). Políticas: `${CLAUDE_PLUGIN_ROOT}/references/routing-policy.md`, `${CLAUDE_PLUGIN_ROOT}/references/risk-policy.md` e `${CLAUDE_PLUGIN_ROOT}/references/models.md`.
